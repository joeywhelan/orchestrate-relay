Agentic ServiceNow Search:
IBM Orchestrate via MCP + Elastic

Natural-language search over ServiceNow — no keywords, no custom integration code.

IBM watsonx Orchestrate · MCP host Elastic Agent Builder · MCP server ServiceNow · data source

Business ValueWhy This Matters

  • Faster incident resolution — agents find the right ServiceNow record from a plain-English description. No ticket number, no exact keyword.
  • Zero integration code — MCP connects Orchestrate to Elastic's search tool out of the box. No custom API glue, no middleware.
  • Semantic understanding over keyword matching — queries that share no words with the indexed text still return the correct results.
  • Everything as code — one Terraform run builds the full stack; one destroys it. The entire demo is a reproducible Jupyter notebook.
Watson Orchestrate→ MCP → Agent Builder→ ES|QL → Elasticsearch← Connector / EC2← ServiceNow

The StackArchitecture

  • Orchestrate hosts the agent; reaches Elastic over MCP / Streamable HTTP with basic auth
  • Agent Builder exposes an ES|QL tool via its MCP server
  • Elastic Serverless (aws-eu-west-2) holds the ServiceNow index with semantic_text mappings
  • Self-managed connector — Docker on EC2, singleton ASG, outbound-only: zero inbound rules, no SSH, self-healing

Step 1Provisioning — Terraform End to End

ModuleCreates

aws_networkEgress-only security group (TCP 443 out) on the default VPC — no inbound rules

One terraform apply builds everything; all outputs land in .env for the notebook. Teardown is one terraform destroy.

Step 2Ingest — Outbound-Only Connector Sync

  • Notebook posts a sync job; the EC2 connector polls Elasticsearch and claims it
  • Connector pulls Incidents, Knowledge, Change Requests, Requested Items from the ServiceNow PDI
  • Records bulk-index into search-servicenow-demo
  • semantic_text fields are vectorised automatically at index time by the .jina-embeddings-v5-text-small inference endpoint
  • The connector host is dark to the Internet — every connection is outbound on 443
# trigger an on-demand full sync
POST /_connector/_sync_job
{ "id": "$CONNECTOR_ID", "job_type": "full" }

# poll until completed, then verify
GET /search-servicenow-demo/_count
→ 46 documents indexed

Step 3Semantic Query — Direct to Elasticsearch

FROM search-servicenow-demo METADATA _score
| WHERE MATCH(short_description, ?query)
     OR MATCH(description, ?query)
| SORT _score DESC | LIMIT 5

query = "people cannot log in
         to company systems"

The query shares zero keywords with the results — this is pure semantic ranking:

numbershort_description_score

BM25 keyword search would miss every one of these.

Step 4Create & Verify the ES|QL Tool

  • Register search_servicenow as an ES|QL tool in Kibana Agent Builder via REST
  • Execute it directly with _execute — no MCP, no agent — to confirm hits and latency first
  • This output is the ground truth the agentic path must reproduce
POST /api/agent_builder/tools        # register
POST /api/agent_builder/tools/_execute
{ "tool_id": "search_servicenow",
  "tool_params": { "query": "…" } }

→ same 5 incidents, ranked identically

Step 5Wire Orchestrate — Connection → Toolkit → Agent

orchestrate connections configure -a elastic_mcp \
  -k basic -u "$MCP_SERVER_URL"
orchestrate toolkits add -k mcp \
  -n elastic-agent-builder \
  --transport streamable_http -t '*'
orchestrate agents import -f agent.yaml
  • The toolkit points at KIBANA_URL/api/agent_builder/mcp — Elastic's MCP server
  • Tools are discovered live over MCP — the tool name never appears in any Orchestrate config
  • agent.yaml binds the toolkit; instructions force tool use — the agent never answers from LLM knowledge

Step 6The Proof — Same Question, Agentic Path

$ orchestrate chat ask --include-reasoning \
    "people cannot log in to company systems"

SummaryTakeaways

  • Elastic connects to ServiceNow out of the box via the self-managed connector — no custom ETL required
  • MCP-based tools in Elastic Agent Builder enforce deterministic tool use from agents
  • IBM Orchestrate connects to Elastic via MCP — natural-language ServiceNow search with no custom API integration
  • The entire stack is reproducible: Terraform + a Jupyter notebook, from zero to agentic search and back
